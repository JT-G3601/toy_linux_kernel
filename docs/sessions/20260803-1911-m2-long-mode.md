## 目标

- 启用 A20 并通过 BIOS E820 收集版本化内存图。
- 从 LBA 128 读取 kernel ELF，动态解析/验证 ELF64 和 program headers。
- 仅将合法 `PT_LOAD` segment 复制到 `p_paddr`，清零 `p_memsz-p_filesz`，且
  根据 E820 确认物理范围可用。
- 建立临时 GDT、低 1 GiB identity map 和 higher-half 映射，开启 PAE/LME/paging。
- 从 ELF `e_entry` 跳转内核，不在 bootloader 中写死入口。
- 向内核传递 `boot_info v1`，并由 64-bit 内核打印 long-mode 确认和 E820 map。
- 对非法 ELF 与内存范围不可用给出明确错误码。

## 实际修改

- 将 `boot/stage2.S` 扩展为包含 16/32/64-bit 三阶段的 M2 loader：启用 A20、
  获取 E820、分批读取 kernel ELF、切换 protected mode、验证/复制 `PT_LOAD`、
  清零 BSS、检查 E820 可用范围、建立 GDT/页表并开启 long mode。
- loader 不写死控制流入口；它验证入口位于可执行 segment 后，将 ELF `e_entry`
  写入 boot info，并在 64 位模式中从该字段间接跳转。
- 新增 `boot_info v1` C ABI；通过 RDI 向内核传递 BIOS drive、E820、ELF 物理/
  虚拟范围和入口，结构大小用静态断言固定为 64 bytes。
- 内核早期 COM1 输出确认 long mode，校验 boot info，打印加载范围与全部 E820
  entries，最后输出 `K2:HALT`。
- Makefile 让 stage2 依赖 kernel ELF，并在汇编时嵌入实际文件大小/扇区数；限制
  staging 为 256 KiB。GCC/Clang 调试信息统一为 DWARF 4，兼容当前 readelf。
- 扩展静态镜像验证和 QEMU 测试，覆盖正常、损坏 `S2OK`、损坏 ELF magic、
  1 MiB 低内存四条路径。
- 接受 ADR-0005，记录 M2 低内存布局、临时页表与 boot info ABI；同步更新 README、
  build/boot 文档和项目状态。
